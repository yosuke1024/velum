# Velum — 試作用プロンプト

以下は効果を実測した万能プロンプトではなく、自由度を残した試作の開始設定です。

## 1. 最初の完成稿を作る

新規の執筆チャットで送信します。プロジェクト資料に velum_riko_writing_brief.md を追加しておきます。

```text
設定資料「velum_riko_writing_brief.md」を使って、リコを主人公にした日本語の短編小説を1本書いてください。

読者はVelumもリコも知りません。設定の紹介ではなく、一つの物語として楽しめて、読み終わったあとにリコの別の話も読みたくなる作品を目指してください。

何が起きるか、誰を登場させるか、視点、語り口、結末は任せます。人物紹介のために設定を全部盛り込む必要はありません。

今回は、行商をしているリコの独立した一編として書いてください。旧日記の続きや、シリーズ全体の謎の解決を求めているわけではありません。

長さは日本語で3,000〜5,000字を目安にしてください。厳密な字数合わせより、場面を十分に描いて一編として読めることを優先してください。

ゲームのスキャン回数、解放条件、章の分割はまだ考えなくて構いません。
企画説明やあらすじではなく、タイトルと完成した本文を出してください。
```

## 2. 独立した別案を作る

候補Aのチャットで「別案」と頼まず、新しいチャットで同じ資料と上の指示を使います。
Claudeでは初回送信前にチャットのMemoryをオフにします。別候補の本文を渡す必要はありません。
比較対象をChatGPTにする場合も、同じ資料・プロジェクト指示・依頼文を使用します。

## 3. 気になった箇所だけを改稿する

選んだ原稿のチャットで送信します。角括弧内を実際の感想に置き換えます。

```text
この原稿を改稿してください。

残したいところ：
［例：ミオが無言で商品を元の位置に戻す場面と、それに対するリコの反応］

読めなかったところ：
［例：中盤で店の由来の説明が続き、二人が今何をしているのか分からなくなった］

この問題を直すために必要な部分を改稿してください。
残したいと伝えた場面の魅力を維持し、必要がなければ全体を別の話へ作り直さないでください。

改稿後のタイトルと本文を出してください。
```

## 4. 初見で意味が通るかを点検する

執筆用Projectの外の新規チャットで、設定資料を付けず、完成稿だけと次の指示を渡します。
これはAIによる不明点検査であり、人間の面白さの最終判定を置き換えるものではありません。

```text
以下の短編を、設定資料や作者の説明を読んでいない初見の原稿として読んでください。
総合点や定型的な称賛は不要です。

1. 主人公が何を望み、何をし、結果どうなった話かを、本文に書かれている範囲で短く説明してください。
2. 状況、人物の行動理由、話のつながりが分からなくなった箇所があれば、該当する文とともに最大3件挙げてください。
3. 主人公の性格が、説明ではなく行動として表れている場面を挙げてください。見つからなければそう答えてください。

設定資料や外部情報で補完せず、本文だけを根拠にしてください。
まだ書き直さないでください。

【本文】
［ここに完成稿を貼る］
```

## 5. 採用する前の設定照合

本文が面白いと判断できた後に、最新の関連Canonと照合します。創作時に省いた資料もここで参照します。

```text
以下の短編をVelumへ採用する前に、関連する最新の世界設定と人物設定に照合してください。

明確な設定矛盾、新しく作った未承認の設定、主人公が知らないはずの情報、時系列への配置上の問題を区別して報告してください。
単に資料に書いていない創作部分を、すべて矛盾として扱わないでください。

原稿や既存のCanonを勝手に変更せず、調整が必要な箇所とその理由を示してください。
```
