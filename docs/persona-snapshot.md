# Persona Snapshot

World と Diary の履歴から、PixTale が使う圧縮済みペルソナを生成する。

**実装状況:** 未実装（M3）。この文書は仕様である。

---

## 1. 何を圧縮するのか

PixTale へ日記の全文を渡すのではない。**人生の結果として残った人物像**へ変換する。

```text
出来事:
  親友に約束を破られた

人物への長期的な影響:
  - 口約束を信用しない
  - 書面や証拠を重視する
  - 親しい相手ほど慎重に距離を測る
```

Tale コメントに必要なのは後者だけである。前者は `characters/<id>/diaries/` に残っていればよい。

## 2. Snapshot に入るもの

- 基本人格（profile 由来の固定層）
- 時代・職業・立場
- 価値観
- 現在の人物状態（要約）
- 重要な人生経験（memories から importance 順に）
- 人間関係から形成された態度——**関係そのものではなく、関係が残した癖**
- 観察時の着眼点（`appraisal.question` / `focus`）
- 偏見・誤解
- 話し方（`voice`）
- 知識境界

## 3. Snapshot に入れないもの

- 日記の全文
- 他の時代・他の人物の情報
- `relationships.yaml` の `hidden_from_protagonist`（**本人が知らない事実は渡さない**）
- `core.secret_unknown_to_self`（同上。ただしその結果として現れる着眼点は入れる）

最後の2つが重要である。テオが「作り手の執念に反応する目」を持っていることを彼自身は知らない。Snapshot に入れるのは「量産品にすら作り手の物語を視てしまう」という**振る舞い**であって、その正体ではない。

## 4. バージョニング

```text
characters/<id>/snapshots/v0007.json
```

Snapshot は追記のみ。既存バージョンを上書きしない。

PixTale Proxy は**バージョンを固定して**読む。したがって:

- こちらの生成が止まっても、PixTale は動き続ける
- Diary 生成が壊れても、直近の安定版ペルソナが使われる
- 不自然な人格変化があれば、ピンを以前のバージョンへ戻すだけで元に戻る

```text
velum: characters/<id>/snapshots/v0007.json
         ↓ 公開ファイルとして取得
PixTale Proxy: KV へキャッシュ → 選ばれた時代と人物の分だけプロンプトへ注入
```

**実行時の連携はこの一方向のファイル取得だけ。** 両リポジトリはデプロイも CI も独立している。コード共有もサービス間連携も、この企画の目的ではない。共有するのは思想・データ形式・生成成果である。

## 5. Tale コメントでの使われ方

```text
1. カメラで撮影された画像を受信
2. 取得時刻の末尾などから時代を疑似ランダムに決定
3. 時代に対応するペルソナを決定
4. 時代情報と Persona Snapshot を取得
5. 画像と必要最小限のコンテキストを Gemini へ送信
6. ペルソナ固有の Tale コメントを返す
```

PixTale は同じ写真を二度利用できず、画像アップロードもできない。カメラから毎回新しく読み込む仕様なので、同じ画像に同じ時代を再現する決定的ハッシュは不要である。取得時刻を使った簡易な時代選択で足り、世界観上は「撮影した瞬間に、ある時代の Echo と共鳴した」と説明できる。

## 6. 個々の日記を、個々のアイテムへ結び付けない

直近の日記の事件を、すべての鑑定へ強引に接続してはいけない。

作りたい接続は次のものである。

> その人生を送った人物だから、そのアイテムをそのように見る。

**このリポジトリは人生の全記録であり、PixTale が使うのはその履歴から生成された Snapshot だけである。** ここで起きた個々の出来事が、鑑定される個々のアイテムの正史になるわけではない。

## 7. 検収

Snapshot が機能しているかは、記憶なしの従来プロンプトとの比較で判定する。

- 人物固有の着眼点・価値観・口調が出るか
- 日記の一事件へ無理に関連付けず、人生全体から自然に語れるか
- Tale コメントだけを読んで、別の人物とは違う人格を感じるか
- **現行 PixTale の笑い・シェアしたくなる強度を落としていないか**

最後の項目が本丸である。PixTale が止まったのは出力が十分に面白くなかったからであり、育った人格が真面目になりすぎて笑いを殺すのは、この企画の最悪の失敗モードである。

各人物の笑いの源泉は `profile.yaml` の `appraisal.humor` に定義してある。声の基準は `tests/fixtures/voice/` にある。
