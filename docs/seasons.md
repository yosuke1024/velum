# 季（シーズン）— 出来事を前もって組み立てる

1人につき5話、5人で25日分の出来事を、季の頭でまとめて計画する。

**実装状況:** 実装済み。`src/season/`、`npm run plan`。

---

## 1. なぜ前もって作るのか

出来事をその日に即興で作ると、**物語の形がどこにもない**。

毎日その場でひとつ出来事を作らせると、モデルは「今日は何が起きるか」だけを考える。発端も転機も決着もなく、昨日の設定を今日が壊す。5日経っても物語が始まらないか、5日とも別方向へ散る。

だから先に5話ぶんを組み立てる。

```text
第1話 発端  問題が具体的な形をとる。まだ引き返せる。
第2話 展開  話が込み入る。単純だと思っていたことが単純でなくなる。
第3話 転機  何かが変わる。前の2話の前提がひとつ崩れる。
第4話 危機  逃げ道がなくなる。選ばなければならなくなる。
第5話 決着  片がつく。ただし世界は終わらない。次の季へ残り火を置く。
```

もうひとつ、こちらのほうが大きい理由がある。**人間が読んで直せる。**

計画は `world/seasons/<季>/<時代>.yaml` に YAML で書き出される。走らせる前に25日分すべてを読み、気に入らない展開を書き換えられる。日ごとの即興ではこれができない——出てきたものを受け入れるか、その日を捨てるかしかない。

## 2. 1季 = 25日

ローテーションは5日で5時代を1周し、5周で1季が終わる。

```text
 1日目 ギルド 第1話    6日目 ギルド 第2話   ...  26日目 ギルド 第1話（第2季）
 2日目 静寂   第1話    7日目 静寂   第2話
 3日目 大収束 第1話    8日目 大収束 第2話
 4日目 破砕   第1話    ...
 5日目 原初   第1話          25日目 原初 第5話（第1季 終わり）
```

各主人公は1季のあいだに5話ぶんの日記を書く。読者は日付順に読むと5つの時代を毎日飛び回り、時代順に読むとひとりの物語を5話続けて追える。**同じ日記が、並べ方で別の意味を持つ。**

## 3. 何を渡して組み立てるか

```text
アーク（world/arcs/）
+ 未解決スレッド（このときは全部渡す。5話の形を作るには一望が要る）
+ 季の始まりの時点での人物状態
+ 前の季が残したもの（第5話の leaves_open）
+ イベントカード（world/cards/ から重み付きで7枚。素材であって出来事ではない）
+ 乱数（季ごとに決まる。同じ季を作り直しても素材は変わらない）
= 5話ぶんの出来事
```

カードは**素材**である。そのまま出来事にせず、アークと人物の状況に照らして具体化する。使わないカードがあってよいので、5話ぶんより多めに引く。

## 4. 世界は計画され、人物は反応する

前もって決めた出来事は、その人がどう変わったかに反応できない。これは避けられないトレードオフであり、次のように分けて受け止める。

| | 決まっているもの | 動くもの |
|---|---|---|
| 日ごと | 何が起きるか | どう受け取り、どう変わるか |
| 季ごと | — | 次の季の計画が、いまの状態から立てられる |

**人物が世界へ反応するのは日ごと、世界が人物へ反応するのは季ごと。** 25日に一度、その時点の人物状態を読んで次の季を組み立てるので、フィードバックは季の境目で入る。毎日反応させると、それは物語ではなくその日の気分の連鎖になる。

## 5. 暦 — 大きな流れに沿わせる

季の計画は Velum の暦の上に立つ（`world/canon/calendar.yaml`）。

- **1年 = 12の月 × 30日 + 五夜（どの月にも属さない5日）= 365日。** 月の名（芽の月〜眠りの月）は原初の星読み由来で、全時代共通。
- 各時代の**祭・節目**は `world/canon/<era>.yaml` の `observances` にある。仮銘審査、北の市、灯の日、星祭り——アークの時限装置はすべて暦の上の日付を持つ。
- 各時代の「いま」は `world/clocks.yaml`。**季の計画が立つたびに、最終話の翌日へ進む。**

### 日付は飛ぶ

各話は `world_date` を持ち、**日付は連続しない**。日記は毎日つけるものではない。季全体で20〜40日ほど進むのが目安で、この速さだと**現実の1年でおよそ世界の1年**が巡る。稼働開始時は全時代が星の月4日（秋の初め）——現実の9月と季節がゆるく重なって進む。

### 年の数え方は時代の声

| 時代 | 年 | 声 |
|---|---|---|
| 原初 | **数えない**（null） | 「星祭りまであと十一の夜」。日付の数字を使わない |
| ギルド | 3,745年 | 年月日。期限と台帳の暦 |
| 大収束 | **4,217年のまま変わらない** | 終わらない年。芽の月一日からの通算日「収束暦」を併記 |
| 破砕 | 5,330年（開戦から1,113年目） | 戦後を知らない世代の暦 |
| 静寂 | 9,745年 | ギルドとの差はちょうど六千年（ヴェスパーの首飾りの糸を数字で支える） |

## 6. canon との関係

`world/canon/<era>.yaml` の `fixed` は固定事実であり、**計画がこれと矛盾したら直す。** `npm run validate` が季の計画も検証するので、手で直したものが壊れていないかも見られる。

固定していない細部（通りの名前、通行人、天候、品物）は自由に作ってよい。即興された細部が繰り返し登場するようになったら、人間が canon へ昇格させる。

## 7. 出来事だけを書く

計画に書くのは「起きたこと」だけで、人物がそれをどう感じたかは書かない。感情・解釈・内面は、このあと本人が日記で書く（[diary.md](diary.md)）。

この分離が効くのは、**事実と主観を別の層に置くことで、日記が事実を上書きできなくなる**からである。日記の中で人物が何を思おうと、起きたことは計画に書かれたままである。

## 8. 時代を跨ぐ糸

`world/threads/cross-era.yaml` に5本の糸がある（聴き手の系譜・制度の系譜・ヴェスパーの首飾り・セヴランの記録帳・五夜）。

**計画のプロンプトへ「この糸を回収せよ」と指示していない。** 人物は自分が糸の一部であることを知らないまま生きる。糸は読者だけが横断して発見できる形で仕込まれており、それが公開リポジトリとしての読み物価値になる。

糸を動かすのは人間である。canon やアークを編集したときにだけ動く。

## 9. 使い方

```bash
npm run plan -- --season 1                 5時代ぶんまとめて計画する
npm run plan -- --season 1 --era guilds    1時代だけ作り直す
npm run plan -- --season 1 --force         計画済みでも上書きする
npm run validate                           直した計画が壊れていないか見る
```

計画を立てたら `world/seasons/001/` を読む。`shape` に、その5話でどういう形を描くのかが2〜3文で書いてある。直したい話があれば YAML を直接編集してよい。番号と beat の並びだけは崩さないこと（validate が落とす）。

## 10. 訳は、直したあとに付ける

サイトは 1言語 = 1 URL である。時代ページ（`/velum/<時代>/`）が季の計画から出すのは **`title` / `shape` / 各話の `leaves_open` の3種類だけ**で、訳が無ければ `/velum/en/` にそのまま日本語が出る。

この3つは `{ ja, en }` で持てるが、**生成は日本語だけを書く。**

```yaml
title:
  ja: 座金の残影
  en: "The Washer's Afterimage"
```

計画を立てた直後に訳を付けないのは、**そのあと人間が直すから**である。§9 のとおり、気に入らない話は YAML を直接書き換える。生成と同時に訳を作ると、日本語を直した瞬間に英語だけが古くなり、公開ページには「読めるが内容の違う英語」が残る。**日本語のまま出ているほうが、まだ壊れていると分かる。**

だから順番はこうなる。

```text
npm run plan  →  人間が読んで直す  →  訳を付ける  →  npm run validate
```

`npm run validate` は未訳の欄を数えて名前で挙げる。落としはしない——立てたばかりの季がまだ訳されていないのは正常だからである。ただし黙って通しもしない。

**日本語を直したら、その欄の `en` も直すこと。** validate は「訳が無い」ことは見つけられるが、「訳が古い」ことは見つけられない。

日記のメタ（タイトル・引用・気分）は逆の扱いで、生成にその場で両方書かせる（[diary.md](diary.md) §6）。日記は人間が直さないので、あとから訳す理由がない。
