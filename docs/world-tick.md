# World Tick Generator

その日、その時代で何が起きたかを生成する。

**実装状況:** 実装済み。`src/tick/`、`npm run day`。

---

## 1. なぜ必要か

背景情報と前回の日記だけでは、同種の日記を反復する。**日々の新しい入力が要る。**

これは順序の制約でもある。World Tick なしで日記生成だけを先に始めてはいけない。反復するのが分かっているからである。

```text
1. World Tick Generator   ← ここから
2. Diary / Persona Growth
3. Persona Snapshot
4. Tale コメント機能
```

## 2. 入力

完全ランダムにはしない。

```text
物語アーク（world/arcs/）
+ 未解決スレッド（アーク内の unresolved）
+ キャラクターの現在状態（characters/<id>/current-state.yaml）
+ イベントカード（world/cards/<era>.yaml から重み付き抽選）
+ 乱数
= 今日の World Tick
```

カードは「その日に起きうることの種」であって、出来事そのものではない。カードを引いてから、アークと現在状態に照らして具体化する。同じカードでも、その人がいま何に焦っているかで別の日になる。

## 3. ローテーション

**進むのは1日ひとつの時代だけ。** ギルド → 静寂 → 大収束 → 破砕 → 原初 の5日周期（`world/canon/rotation.yaml`）。

番でない時代の World Tick は生成しない。その時代の時間は止まっている。5人が並行して生きているのではなく、**5つの時代が順番に1日ずつ進む**。

## 4. canon との関係

`world/canon/<era>.yaml` の `fixed` は固定事実であり、**生成がこれと矛盾したら、その日を破棄する。**

固定していない細部（規約の条文番号、通りの名前、通行人など）は生成の即興を許す。即興された細部が繰り返し登場するようになったら、人間が canon へ昇格させる。

## 5. 出力

```text
world/ticks/<YYYY>/<MM>/<YYYY-MM-DD>.json
```

Tick は「起きた事実」であって、人物がどう受け取ったかではない。認識と解釈は Diary 側の仕事である（[diary.md](diary.md)）。

この分離が効くのは、同じ出来事を複数の人物が別々に解釈しうるからではなく——実際には1日ひとりしか書かない——**事実と主観を別の層に置くことで、日記が事実を上書きできなくなる**からである。

## 6. 時代を跨ぐ糸

`world/threads/cross-era.yaml` に4本の糸がある。

**生成プロンプトへ「この糸を回収せよ」と指示してはいけない。** 人物は自分が糸の一部であることを知らないまま生きる。糸は読者だけが横断して発見できる形で仕込まれており、それが公開リポジトリとしての読み物価値になる。

糸が動くのは、人間が canon やアークを編集したときだけである。
